# AI Mode Citation Review

## AI Mode Citation Review Conversational Scope

This note reviews whether a blog page can support deeper, follow-up-driven AI Mode tasks. It differs from an AI Overview review because AI Mode can continue the search session through refinements, comparisons, and planning questions. Google reported major AI Mode adoption at I/O 2026 (`blog-io2026`), but that product-reach statement does not equal a site's traffic opportunity.

Use `g-ai-features` for the documented Search surface, `ahrefs-aio-vs-aimode` for the AS-REPORTED finding that AI Mode and AIO citation sets can differ, and `semrush-ai-mode-comparison` only as practitioner context about answer-link patterns. The SparkToro source `sparktoro-zero-click-2026` is useful for proportional budgeting because it gives AI Mode share context in a third-party US panel; keep that claim routed through [[AI Citation Mechanics]] and do not repeat it as a universal forecast.

### Query Chains This Note Owns

Own review of multi-step user needs such as comparison, troubleshooting, planning, eligibility, and selection queries where one page may need answer blocks for several sub-decisions.

### Budget Boundaries For AI Mode Work

Do not move budget from classic organic fixes or AI Overview basics unless query logs, audience research, or Search Console reporting show that AI Mode-style journeys matter for the topic.

## AI Mode Citation Review Procedure

1. Write the likely initial query and at least two follow-up questions.
2. Map each follow-up to one page section, not to a generic page-level score.
3. Check whether the answer block names the entity, comparison set, date, and constraint.
4. Mark missing data as a measurement gap rather than a reason to invent priority.
5. Send copy fixes to [[Passage Citability Checklist]] and measurement gaps to [[Citation Exposure Metrics]].

## Worked Query Chain

A software buying guide is reviewed for the initial query "best appointment app for solo clinics". The first follow-up asks for migration constraints, and the second asks which option supports recurring visits. `g-ai-features` supports treating this as a Google AI feature review, while `semrush-ai-mode-comparison` stays practitioner context about answer-link patterns.

The article's opening comparison table names three products, but the migration section says "this option" without naming the product. The review sends that block to [[Entity Clarity For AI Answers]] before any readiness label, because `ziptie-aio-source-selection` supports self-contained passage construction as advisory evidence.

If the stakeholder cites Google's I/O adoption statement, the recommendation keeps it at product-reach context only. `blog-io2026` cannot turn one clinic topic into a forecast for impressions, clicks, or citations.

## AI Mode Failure Patterns

- The reviewer scores only the first answer and ignores follow-up tasks, weakening the AI Mode-specific review.
- A visible AIO citation is treated as AI Mode readiness, despite the citation-divergence warning supported by `ahrefs-aio-vs-aimode`.
- Product adoption context from `blog-io2026` becomes a site traffic forecast.
- A screenshot lacks the query chain, locale, and date, so [[Citation Exposure Metrics]] must mark it as observation-only with `g-ai-features`.

## Brief Wiring

[[Content Brief Output Contract]] consumes this note when the brief includes AI Mode-oriented section jobs. It needs the initial query, follow-up questions, entity list, constraint list, and source IDs attached to each section job.

The expected output is not a citation target. The brief should receive a bounded instruction such as "add migration branch", "name comparison entities", or "defer AI Mode work until measurement exists".

## Follow-Up Coverage Markers

Comparison sections should name every alternative before citing practitioner context from `ahrefs-aio-vs-aimode`.

Planning sections should expose the constraint, sequence, and owner before using `semrush-ai-mode-comparison`.

Eligibility sections should identify excluded cases, because `g-ai-features` does not support hidden assumptions.

Budget notes should keep `blog-io2026` product context separate from page-level opportunity language.

## AI Mode Citation Review Output

The output is a short recommendation that says whether the page is ready for AI Mode-style answer review, needs section rewrites, or should wait for stronger evidence. It must not promise citation, click lift, or Google feature inclusion.
