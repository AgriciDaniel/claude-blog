# llms.txt Caveat Note

## llms.txt Caveat Note Citation Job

This note handles proposals to create, edit, or promote `llms.txt` as part of AI citation work. Its job is to keep the distinction clear: the `llms.txt` proposal may be relevant to non-Google LLM consumers, but Google's own Search guidance says it is not used for Google Search, AI Overviews, or AI Mode visibility. The high-confidence Google evidence is `g-ai-opt-guide` plus `g-update-2026-06-15-llms-txt-clarified-as-unused-by-google-search`; the proposal source is `llmstxt`; feature context can cite `g-ai-features`.

### Passage, Entity, Or Surface This Note Owns

Own the caveat paragraph in any brief, audit, or recommendation that mentions `llms.txt`, AI files, machine-readable summaries, or file-based visibility shortcuts.

### No-Guarantee Boundary For AI Inclusion

A site can maintain `llms.txt` for other consumers if the team has a reason, but this brain must not present it as a Google Search ranking, AI Overview, or AI Mode requirement.

## llms.txt Caveat Note Remediation Procedure

1. Quote the stakeholder's intended use in one sentence.
2. Label the target as Google Search, Google AI feature, or non-Google consumer.
3. Apply the Google caveat when the target is Search, AI Overview, or AI Mode.
4. If the target is non-Google, require an owner and refresh process before recommending the file.
5. Route normal passage work to [[Passage Citability Checklist]].

## Stakeholder Request Example

A publisher asks for a sprint to create `llms.txt` because a competitor has one. The caveat response says the file may be maintained for named non-Google consumers if the publisher has an owner and refresh process, using `llmstxt` as proposal-level support.

The same response says the file should not be described as a Google Search, AI Overview, or AI Mode visibility requirement. That caveat cites `g-ai-opt-guide` and `g-update-2026-06-15-llms-txt-clarified-as-unused-by-google-search`.

If the competitor also blocks Google-Extended, the discussion moves away from `llms.txt`. `g-common-crawlers` covers that crawler-control topic, while `g-ai-opt-guide` keeps Search visibility claims grounded in normal content and crawling foundations.

## llms.txt Failure Cases

- The file is added, but no owner updates URLs or stale summaries, weakening any non-Google utility supported by `llmstxt`.
- A recommendation says "required for AI Overviews", contradicting `g-update-2026-06-15-llms-txt-clarified-as-unused-by-google-search`.
- The file is used to mask weak passages instead of fixing entity clarity and source proximity.
- Google-Extended, robots.txt, and `llms.txt` are merged into one tactic, despite separate source coverage in `g-common-crawlers`.

## SEO Check Wiring

[[SEO Check Validation Checklist]] consumes this note when a final review mentions AI files or machine-readable summaries. It needs the proposed file purpose, target surface, owner, refresh cadence, and Google caveat wording.

The checklist expects a pass, caveat, or block: pass for non-Google inventory with owner, caveat for neutral mention, block for any Google visibility promise.

## Caveat Text Shape

Start with the target consumer, because `llmstxt` alone is proposal-level support.

Name Google Search, AI Overviews, or AI Mode only with `g-ai-opt-guide`.

Attach the June 2026 clarification source when rejecting Google visibility promises.

Keep Google-Extended language under `g-common-crawlers`, not under llms.txt.

## llms.txt Caveat Note Handoff

The clean output is a caveat, not a task ticket. If a future Google source changes the position, update [[2026 Google Update Timeline]] and then revisit this note.
